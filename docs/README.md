## 关键设计决策记录（ADR 摘要）

1. **交付边界**：模块化单体；首版不做赛程、比分、评分与晋级算法。队伍、准入和两级审核保留里程碑 2。
2. **权限边界**：单位树与赛事作用域独立；赛事创建、管理角色分配仅平台管理员。证件更正允许所属单位管理员审核本范围普通成员，禁止自审。
3. **赛事结构**：所有业务挂届次；赛项与组别正交，通过 offering 显式开放合法组合。
4. **队伍身份**：队号只能归属一个单位，队号×跨届稳定赛项定义队伍；晋级准入跟随队伍身份，由单位管理员统一管理全部队伍，创建和资料修改各自审核且禁止自审；学生全平台一支当前队伍，换队先退后入并保留历史。
5. **本场冻结**：每轮提交冻结资料、成员、文件、所选学段及审核模式；队伍主档独立更新。未审可取消修改，已通过须审核员驳回再重提，历史版本保留。
6. **人工选学段**：提交人选择开放组别对应学段；仍校验配置的年龄/年级/成员条件，审核员核验。
7. **账号与证件**：自助邮箱注册，单位可代建无邮箱学生账户；支持证件+密码登录。参赛成员身份证/护照二选一，Fernet 加密、HMAC 当前绑定唯一；更正批准后释放旧号，注销不自动释放，不能自动识别同人不同证件。
8. **可靠异步**：验证码统一 202 受理，任务侧判断并发送；业务与 outbox 同事务，补投与消费幂等，不将受理等同送达。
9. **逐人证书**：获奖固定审核通过的提交轮次，仅奖励学生参赛成果，按该轮学生队员逐人发证；证书编号永久不变，补发保留原证链，旧名单任务按版本失效。
10. **历史可见性**：关闭届次保留业务资料，管理端按范围查询，普通入口隐藏；公开证书验证仍提供最小有效性结果。

术语见 [GLOSSARY.md](../GLOSSARY.md)；完整规则分别在 01–07 维护。
