## 关键设计决策记录（ADR 摘要）

1. **定位收窄**：第一版不做赛程编排、对阵、实时比分、晋级算法、在线评分。
2. **角色与组织身份分离**：`users` + `user_profiles`（人员身份：队员/教练）与 `roles`（管理角色：单位管理员/赛事管理员等）两套体系，一个人可同时持有多身份多角色，不需要多账号。
3. **组别独立建模**：组别配置（报名类型、人数限制、材料要求）不写死在赛事表，见 `competition_groups`。
4. **一切业务数据挂届次**：报名、获奖名单、证书、统计均关联 `competition_editions`（届次），不直接关联 `competitions`，保证多届数据天然隔离。
5. **报名成员快照**：`registration_members` 保存提交时点的人员信息快照，队伍后续换人不影响历史参赛记录。
6. **审核先做单级**：里程碑 1 只实现"赛事审核"；两级审核（单位初审 + 赛事复审）作为赛事级配置在里程碑 2 加入，两种模式共用同一套状态机。
7. **静态报名表单**：里程碑 1 采用固定字段 + 每组别不同的附件/必填项配置；动态表单引擎为 P1，见任务拆解。
8. **通知 = 站内消息 + Celery 发邮件**：短信、第三方认证为 P2。
9. **模块化单体**，不用微服务；按 Django app 划分模块边界。
10. **届次匹配规则**：获奖名单 Excel 导入以报名流水号（`registration.batch_no`）为主键关联，身份证号仅作辅助校验，不靠姓名匹配。
