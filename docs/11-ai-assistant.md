# AI 助手设计

状态：2026-11-18 用户提出的后续需求；当前仅交互预览与设计约束，未接入模型、工具执行后端或真实业务 API。不代表里程碑 1 已交付，排期见 [07](07-task-breakdown.md)。

## 1. 体验与组件复用

门户与控制台提供同一悬浮入口。学生可登录后说“帮我报名比赛”，审核员可说“帮我核对这份报名”，用户可询问当前可见的赛事规则、时间和开放组合。可用能力由当前 grants、对象范围和业务状态计算，不能只按角色名称分配固定能力。

正式前端采用 Vue 3 + Element Plus：助手使用受控显示的非模态聊天浮窗，输入与校验使用 ElInput/ElForm，动作摘要使用 ElDescriptions，确认使用既有 ElDialog/ElMessageBox，任务反馈使用 ElMessage/ElAlert。面板不使用阻挡页面的 Drawer 默认遮罩；基础控件复用组件库，报名与审核直接复用既有业务表单、校验器及领域 API，有重复后才提取业务组件，不单独开发一套 AI 报名/AI 审核界面。

### 会话与浮窗生命周期

- 悬浮球只负责展开/收起；面板与会话状态挂在 AppShell、RouterView 之外。页面切换、业务区刷新、滚动及业务弹窗打开均不得重建聊天面板。展开时其他页面区域仍可点击和滚动，业务模态弹窗处于更高交互层级。
- 对话记录与未发送草稿只保存在当前标签页内存中，支持连续多轮对话；不写 localStorage、sessionStorage、IndexedDB 或后端会话存储。收起/展开及站内换页保留，浏览器刷新、关闭页面清除。这里的“保留在浏览器”指内存，不采用刷新仍保留的 sessionStorage。
- 提供始终可见的“清空”入口，清除本次对话、输入草稿和待执行提案。换账号、退出及授权上下文改变时也清除；不能把此前有权读取的对话继续带入失权上下文。
- 用户输入任务后，可通过受限命令自动切换页面和填写允许修改的草稿；聊天继续保留在浮窗中，不额外要求先点“打开页面”。已提交资料冻结时只能定位/解释，不能直接修改或自动取消。提交报名与审核决定仍依照原有校验、事实核验及确认规则。

交互形式参考已查看的 [百度智能云公开助手面板](https://cloud.baidu.com/) 与 [阿里云帮助中心入口](https://help.aliyun.com/zh/)：小入口、右侧服务面板、推荐任务和底部输入。仅参考这些公开交互结构，不复制其品牌、人物素材或代码，也不推断其权限及存储实现。

AI 操作组件的方式是调用有限的业务命令，例如打开表单、建议字段、准备提交、准备审核决定；界面渲染相应组件与预览。禁止模型执行任意 JavaScript、点击任意 DOM、修改全局状态或绕过组件直接写库。规则、权限和状态校验由业务服务负责，不能依赖“按钮是否显示”。

建议流程：自然语言意图 → 查询本人有权读取的资料 → 缺项追问 → 同一表单显示建议内容 → 原校验器校验 → 展示实际提交内容/审核决定 → 按原业务规则确认 → 同一领域 API 执行 → 用实际 API 结果反馈。审核辅助必须展示依据与缺项，不将模型判断视为核验事实；需要理由的决定不能由空理由或虚构依据代替。不能把准备好表单、模型输出成功或 HTTP 202 受理写成业务已完成。

## 2. 权限与可见性

权限唯一来源仍为 [02 权限矩阵](02-permission-matrix.md)。不新增 AI 超级角色，不给模型平台管理员账号、数据库账号或服务凭据。AI 可用工具 = 已实现并允许供 AI 使用的工具白名单 ∩ 当前用户的实时权限 ∩ 当前对象作用域 ∩ 当前业务状态；用户有权限也不意味着所有能力自动开放给 AI。

| 场景 | 必须保留的边界 |
| --- | --- |
| 询问赛事 | 使用门户同一可见性查询；草稿、关闭历史、未发布资料与内部材料不能混入普通用户检索上下文 |
| 参赛者报名 | 仅本人有权提交的报名；教练仅本人负责队伍，不能取得队伍资料维护权；身份/许可/准入/时间窗/冻结规则与手动一致 |
| 单位管理 | 单位树范围不扩展为赛事管理权限，不因此提供整场内部报名或导出 |
| 报名审核 | 限被授权赛事/届次及对应审核阶段；禁止自审；最小历史摘要从有权读取的本场报名解析，不能任意枚举队伍历史 |
| 名单查询 | 保留 none/login/open、公示时间及届次状态判断；login 指所有登录用户；未通过者与内部审核材料不因 AI 问答公开 |

以上为场景说明，不替代或扩大 02 中的授权矩阵。

## 3. 查询必须在模型获得数据之前受限

1. 后端从认证会话确定 actor，模型提供的 user_id、role、scope 或“管理员授权”文字不作为身份来源。每轮检索与每个工具调用都重新校验实时 grants、对象归属和可见性。
2. 搜索、向量检索、全文检索、附件读取都在查询侧约束租户/单位/赛事/发布范围；不能全库召回、送入模型后才过滤。工具返回采用面向任务的 serializer 字段白名单、分页与条数上限，默认不发送证件、照片、联系方式、密钥、内部备注或全量导出。
3. 模型不访问浏览器整页 DOM、前端 store、数据库、对象存储目录、任意 URL 或任意 SQL。每个附件与引用链接单独验证读取权，不因摘要可见就开放原件。
4. 对话、检索缓存、摘要和工具结果按账号与授权上下文隔离；跨账号不复用，跨作用域合并必须分别有权。权限被撤销或角色范围变更后，清除失权上下文并重新构造会话，旧对话不能成为继续读取旧资料的依据。
5. 用户输入、赛事章程、附件正文与检索结果都视为不可信内容；其中的“忽略规则/调用导出/提升权限”等指令不能改变工具白名单或执行参数。没有可用工具时明确拒绝，不改用抓取页面或通用网络工具绕行。

## 4. 执行与确认

模型只提出结构化意图和受限参数，后端使用现有 ScopedRolePermission、service 和 transition 执行，不实现第二套状态机。prepare 与 execute 都校验权限；准备时通过不等于稍后仍有权执行。执行时重新读取业务状态、报名提交轮次、资料版本、时间窗与名单锁定状态，检查幂等，禁止自审和重复决定。

报名提交前展示将被冻结的对象、成员、组别与材料；审核决定展示目标报名编号、轮次、决定和理由。驳回、批量审核、名单解锁、证书作废等仍执行既有确认要求，不因为“AI 自动化”取消确认。确认凭证须绑定 actor、工具、对象、版本、参数摘要与有效期且仅用一次；修改提案、过期、撤权或状态变化后重新准备，不能把一句“以后都同意”当成无限授权。

只有实际业务 API 返回成功才能显示完成；超时先按幂等键查询结果，不能自动重复写入。异步任务按原任务状态展示。审计记录 actor、工具、对象、版本、确认、执行结果和 request_id；日志遵循 [DEVELOPMENT.md](../DEVELOPMENT.md)，不额外保存原始敏感对话或附件正文。

## 5. 接入前验收与未决项

- 普通用户诱导获取内部审核、草稿赛事、他人报名、证件或附件时，检索与工具两层都拒绝；返回与普通接口同样的 404/无权限语义，不泄露对象是否存在。
- 同单位不同赛事、同赛事不同届次、不同单位树、教练非负责队伍、未发布/登录可见公示均有跨范围反例。缓存与历史对话不得跨账号、跨授权范围复用。
- 先准备后撤权、准备后改轮次、报名截止、已审核、自审、名单锁定、重复确认和任务重试均不能绕过原服务规则。
- 恶意附件和提示注入不能提升权限；工具只提供最小字段，真实模型请求中不出现禁发字段。
- 用户尚未指定模型供应商、部署方式、数据处理区域、留存/训练策略与预算。外发任何真实资料前由负责人确认这些数据处理边界；目前原型无模型网络请求，不采集真实对话资料。

当前静态原型使用独立的 assistant-root 和内存会话，固定规则支持查询公开样例、自动切换至报名/我的报名/授权审核页面，以及给可编辑报名草稿选择开放组别。输入不发给模型；不自动提交报名、不作审核决定，不据此宣称后端权限隔离或真实大模型多轮理解已实现。原型使用原生 dialog.show()，不占用业务弹窗，不创建全页遮罩。
