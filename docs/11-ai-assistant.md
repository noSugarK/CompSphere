# AI 助手设计

状态：2026-11-18 用户提出的后续需求；当前仅交互预览与设计约束，未接入模型、工具执行后端或真实业务 API。不代表里程碑 1 已交付，排期见 [07](07-task-breakdown.md)。

已确认首批真实接入范围为赛事问答、报名辅助与审核辅助，先向受邀账号开放并限制额度，再根据权限隔离、准确性、成本与滥用防护结果扩大开放。AI 不可用或额度耗尽时仍能手动完成业务；真实接入不作为首期核心闭环交付的前置条件。供应商处理条件、配额及预算未确认前不发送真实资料。

## 1. 体验与组件复用

门户与控制台提供同一悬浮入口。学生可登录后说“帮我报名比赛”，审核员可说“帮我核对这份报名”，用户可询问当前可见的赛事规则、时间和开放组合。可用能力由当前 grants、对象范围和业务状态计算，不能只按角色名称分配固定能力。

正式前端采用 Vue 3 + Element Plus：助手使用受控显示的非模态聊天浮窗，输入与校验使用 ElInput/ElForm，动作摘要使用 ElDescriptions，确认使用既有 ElDialog/ElMessageBox，任务反馈使用 ElMessage/ElAlert。面板不使用阻挡页面的 Drawer 默认遮罩；基础控件复用组件库，报名与审核直接复用既有业务表单、校验器及领域 API，有重复后才提取业务组件，不单独开发一套 AI 报名/AI 审核界面。

### 会话与浮窗生命周期

- 悬浮球只负责展开/收起；面板与会话状态挂在 AppShell、RouterView 之外。页面切换、业务区刷新、滚动及业务弹窗打开均不得重建聊天面板。展开时其他页面区域仍可点击和滚动，业务模态弹窗处于更高交互层级。
- 对话记录与未发送草稿只保存在当前标签页内存中，支持连续多轮对话；不写 localStorage、sessionStorage、IndexedDB 或后端会话存储。收起/展开及站内换页保留，浏览器刷新、关闭页面清除。这里的“保留在浏览器”指内存，不采用刷新仍保留的 sessionStorage。
- 提供始终可见的“清空”入口，清除本次对话、输入草稿和待执行提案。换账号、退出及授权上下文改变时也清除；不能把此前有权读取的对话继续带入失权上下文。
- 用户输入任务后，可通过受限命令自动切换页面和填写允许修改的草稿；聊天继续保留在浮窗中，不额外要求先点“打开页面”。已提交资料冻结时只能定位/解释，不能直接修改或自动取消。提交报名与审核决定仍依照原有校验、事实核验及确认规则。

聊天组件候选与动画实现按前端设计规范 §7：正式 Vue 内容区优先评估 Element-Plus-X，原型使用既有消息/命令模型与 Anime.js。只对最新消息添加进入反馈；用户阅读历史时不强制滚到底部。拖动和复位仅改变浮窗位置，不影响会话、业务页面、权限或当前表单内容。

消息展示补充参考 [AICSS](https://www.aicss.dev/)：紧凑活动标记、文本与动作分层、可展开动作回执。回执仅记录实际页面动作的名称和结果，错误/拒绝需可读；不得暴露隐藏推理、伪造处理时长、将打开表单写成业务提交成功。真实问答引用仍须逐项鉴权。参考及许可边界见 [09 §5](09-开源参考调研.md#5-本轮演示采用记录与-aicss-补充参考)。

交互形式参考已查看的 [百度智能云公开助手面板](https://cloud.baidu.com/) 与 [阿里云帮助中心入口](https://help.aliyun.com/zh/)：小入口、右侧服务面板、推荐任务和底部输入。仅参考这些公开交互结构，不复制其品牌、人物素材或代码，也不推断其权限及存储实现。

AI 操作组件的方式是调用有限的业务命令，例如打开表单、建议字段、准备提交、准备审核决定；界面渲染相应组件与预览。禁止模型执行任意 JavaScript、点击任意 DOM、修改全局状态或绕过组件直接写库。规则、权限和状态校验由业务服务负责，不能依赖“按钮是否显示”。

建议流程：自然语言意图 → 查询本人有权读取的资料 → 缺项追问 → 同一表单显示建议内容 → 原校验器校验 → 展示实际提交内容/审核决定 → 按原业务规则确认 → 同一领域 API 执行 → 用实际 API 结果反馈。审核辅助必须展示依据与缺项，不将模型判断视为核验事实；需要理由的决定不能由空理由或虚构依据代替。不能把准备好表单、模型输出成功或 HTTP 202 受理写成业务已完成。

## 2. 权限与可见性

权限唯一来源仍为 [02 权限矩阵](02-permission-matrix.md)。不新增 AI 超级角色，不给模型平台管理员账号、数据库账号或服务凭据。AI 可用工具 = 已实现并允许供 AI 使用的工具白名单 ∩ 当前用户的实时权限 ∩ 当前对象作用域 ∩ 当前业务状态；用户有权限也不意味着所有能力自动开放给 AI。

前后端权限控制及数据库隔离的统一规则见 [02 §5](02-permission-matrix.md#5-前后端落地约定)。调用链为：前端权限检查 → 已认证的后端 AI 网关 → 当前用户可用工具列表 → 逐次鉴权的业务接口/命令 → 原业务 service。模型仅产生工具名与受限参数，网关持有并绑定服务端认证上下文，不将用户 token 发给模型；业务后端负责数据库访问，模型与模型适配层没有数据库权限或直连路径。

| 场景 | 必须保留的边界 |
| --- | --- |
| 询问赛事 | 使用门户同一可见性查询；草稿、关闭历史、未发布资料与内部材料不能混入普通用户检索上下文 |
| 参赛者报名 | 仅本人有权提交的报名；教练仅本人负责队伍，不能取得队伍资料维护权；身份/许可/准入/时间窗/冻结规则与手动一致 |
| 单位管理 | 单位树范围不扩展为赛事管理权限，不因此提供整场内部报名或导出 |
| 报名审核 | 限被授权赛事/届次及对应审核阶段；禁止自审；最小历史摘要从有权读取的本场报名解析，不能任意枚举队伍历史 |
| 名单查询 | 保留 none/login/open、公示时间及届次状态判断；login 指所有登录用户；未通过者与内部审核材料不因 AI 问答公开 |

以上为场景说明，不替代或扩大 02 中的授权矩阵。

## 3. 查询必须在模型获得数据之前受限

1. 后端从认证会话确定 actor，模型提供的 user_id、role、scope 或“管理员授权”文字不作为身份来源。每轮检索与每个工具调用都重新校验实时 grants、对象归属和可见性。
2. 搜索、向量检索、全文检索、附件读取都在查询侧约束租户/单位/赛事/发布范围；不能全库召回、送入模型后才过滤。工具返回采用面向任务的 serializer 字段白名单、分页与条数上限，默认不发送证件、照片、联系方式、密钥、内部备注或全量导出。
3. 模型不访问浏览器整页 DOM、前端 store、数据库、对象存储目录、任意 URL 或任意 SQL。当前允许页面提供经白名单投影的任务上下文，规则见下节；每个引用单独验证读取权，不因摘要可见就开放原件。
4. 对话、检索缓存、摘要和工具结果按账号与授权上下文隔离；跨账号不复用，跨作用域合并必须分别有权。权限被撤销或角色范围变更后，清除失权上下文并重新构造会话，旧对话不能成为继续读取旧资料的依据。
5. 用户输入、赛事章程、附件正文与检索结果都视为不可信内容；其中的“忽略规则/调用导出/提升权限”等指令不能改变工具白名单或执行参数。没有可用工具时明确拒绝，不改用抓取页面或通用网络工具绕行。

### 3.1 当前页面上下文与填报排障

- 助手可自动获取当前页面与任务相关、用户有权查看的信息，帮助解释填报/报名错误。每类页面定义字段白名单，只提供页面/步骤标识、对象引用、允许的非敏感草稿值、开放选项、字段校验错误及脱敏后的业务错误码。用户可以查看本轮带入的信息；不采集整页 DOM、截图、完整 store、控制台日志、原始网络响应或隐藏字段。
- 页面投影不是授权凭证，后端仍校验 actor、对象及工具参数；客户端提供的错误文本也视为不可信输入，不将其当作服务端状态事实。需要确认状态时通过同一用户权限内的业务接口重新查询。
- 默认不向模型发送或在 AI 会话上下文中采集证件原文、联系方式、照片、图片、授权原件或附件正文；首批不提供 AI 图片/附件上传、OCR 或视觉识别。在读证明继续经原业务表单上传和人工审核，AI 只接收有权显示的缺失/待核验/通过/退回状态及脱敏原因。用户手动粘贴的敏感信息也须在发送前校验和脱敏，无法可靠处理时阻止发送并提示改用原业务表单。
- AI 可自动定位页面及修改允许编辑的草稿，复用原字段选项、校验与错误反馈；冻结资料不能修改，不能自动取消报名。提交报名、取消报名及审核决定等业务状态变更须显示具体内容后由用户确认，沿用 §4 的执行约束。
- 页面切换后重新生成当前上下文，发送前绑定页面/对象/草稿版本；迟到建议应用前复核目标和版本，不能写入新页面或覆盖用户之后的修改。清空、退出或授权变化取消相关任务并丢弃迟到结果。减少重复采集，不把浏览过的所有页面拼成持续扩大的上下文。

## 4. 执行与确认

模型只提出结构化意图和受限参数，后端使用现有 ScopedRolePermission、service 和 transition 执行，不实现第二套状态机。prepare 与 execute 都校验权限；准备时通过不等于稍后仍有权执行。执行时重新读取业务状态、报名提交轮次、资料版本、时间窗与名单锁定状态，检查幂等，禁止自审和重复决定。

报名提交前展示将被冻结的对象、成员、组别与材料；审核决定展示目标报名编号、轮次、决定和理由。驳回、批量审核、名单解锁、证书作废等仍执行既有确认要求，不因为“AI 自动化”取消确认。确认凭证须绑定 actor、工具、对象、版本、参数摘要与有效期且仅用一次；修改提案、过期、撤权或状态变化后重新准备，不能把一句“以后都同意”当成无限授权。

只有实际业务 API 返回成功才能显示完成；超时先按幂等键查询结果，不能自动重复写入。异步任务按原任务状态展示。审计记录 actor、工具、对象、版本、确认、执行结果和 request_id；日志遵循 [DEVELOPMENT.md](../DEVELOPMENT.md)，不额外保存原始敏感对话或附件正文。

## 5. 防代理盗用、接口滥用与网络安全

本节“防代理盗用”指防止第三方将竞云接口包装为自己的模型服务、盗刷额度或转售访问能力。接口地址、前端混淆、CORS、Origin/Referer 和提示词均不能证明调用者是官方页面；持有合法凭据的脚本仍可能调用接口。目标是限制可调用能力与最大损失，并能发现和终止滥用，不承诺完全阻止转发。

### 5.1 入口身份与计量

- 正式模型请求走竞云后端网关，以既有认证会话确定 actor；浏览器不得持有供应商密钥，也不提供可匿名消耗模型额度的公共代理。公开门户仍可展示静态帮助和既有公开赛事信息，不等于开放匿名模型接口。
- 复用 [05](05-architecture.md) 的 Access/Refresh 机制；客户端提交的账号、角色、模型名和额度值均不可信。模型接口不向客户端签发供应商凭据，不通过 URL 携带 token；登出、封禁、撤权后拒绝后续请求与工具执行，并终止相关活动流。
- Redis 等共享存储按账号限制请求频率、同时生成数、输入/输出 token、上下文长度、工具调用轮数和日用量；单位及平台再设总预算上限。IP 仅作辅助，兼顾学校共用出口，不能通过更换 IP 绕过账号额度；客户端 IP 按 [日志规范](../DEVELOPMENT.md#21-输出与关联) 从受信代理链解析。
- 模型调用前原子预占输出上限对应额度，完成后按实际用量结算；失败、超时、取消及断连均对账，已产生的供应商费用不能因请求未完成而漏计。并发配额不能靠多标签、多实例或自动重试绕过；供应商用量不明时保留待对账占用，避免重复释放。
- 超额按既有 [06](06-api-spec.md) 限流语义拒绝并提供可重试时间；限流/预算存储不可用时暂停新模型调用，保留普通业务操作。重试次数有上限，不自动切换到无预算控制的备用入口。

### 5.2 受限模型出口与工具

- 模型供应商、模型、base URL、请求路径和请求头由部署配置与服务端白名单确定；用户和模型不能指定转发目标、自带 Authorization、切换任意模型或提交供应商原始请求体。网关只接受业务定义的消息及命令 schema，禁止透传任意请求，避免成为通用代理。
- 模型网关只具备必要的出站网络权限，不开放入站公网直连供应商适配层。禁止任意 URL 抓取；未来如需抓取，单独评审 SSRF 防护，覆盖私网/环回/链路本地/云元数据、IPv6、DNS 重绑定与每次重定向，并由网络出口策略兜底。
- 工具参数、名称、调用次数与结果均按白名单校验；不提供 shell、任意代码、SQL、通用 HTTP 或全页面控制能力。用户和附件中的提示注入不能改变身份、目标地址、工具权限或预算。
- 每次检索和工具执行遵循 §2–4；活动流中的撤权/取消会阻断后续工具，已提交业务动作按原业务状态查询，不能把取消生成视作业务回滚。

### 5.3 浏览器、传输与服务保护

- 生产全链路使用 TLS，验证模型供应商证书；密钥只保存在服务端受控配置中，按环境与用途隔离、可轮换和撤销。禁止为调试关闭 TLS 验证，不在浏览器、构建产物、错误响应和日志中暴露密钥。
- 默认同源访问并限制 Host/允许的 Origin；跨域仅按明确来源配置，不使用带凭据的通配允许。沿用现有认证与 CSRF 机制，Origin 检查是补充，不能代替认证或额度校验。上游认证/转发头由受信入口覆盖，拒绝客户端伪造内部身份头。
- 用户消息、模型输出与检索内容按不可信文本渲染；Markdown 如启用则禁用原始 HTML，过滤危险协议，不执行脚本或模型生成的组件代码。不自动加载模型给出的外链图片/远程内容，避免通过资源请求泄露对话；引用与附件仍逐项鉴权，不能把 token 或私有资料拼进外链。
- 反向代理和应用共同限制请求体、消息数、单轮时长、流式连接数及空闲时间；断连向上游传播取消，设服务端总时限兜底。流式响应与模型结果不进入共享 CDN/代理缓存；授权变化、清空或换账号后丢弃迟到响应，不重新填回已清除的对话。
- 按 [DEVELOPMENT.md](../DEVELOPMENT.md) 记录 request_id、actor、供应商/模型标识、用量、耗时及拒绝原因，不记录原始对话、认证头或附件正文。异常用量可关联到账号并暂停模型能力；提供平台预算熔断和供应商密钥紧急撤销流程，暂停 AI 不影响手动报名与审核。

## 6. 接入前验收与未决项

- 普通用户诱导获取内部审核、草稿赛事、他人报名、证件或附件时，检索与工具两层都拒绝；返回与普通接口同样的 404/无权限语义，不泄露对象是否存在。
- 绕过前端路由/按钮、篡改 grants、直接构造工具调用、调用未下发工具或替换对象 ID 均被后端拒绝；验证模型请求及工具 schema 不含认证凭据、数据库连接或 SQL/ORM 能力。手动接口与 AI 工具对同一越权对象得到一致拒绝结果。
- 同单位不同赛事、同赛事不同届次、不同单位树、教练非负责队伍、未发布/登录可见公示均有跨范围反例。缓存与历史对话不得跨账号、跨授权范围复用。
- 先准备后撤权、准备后改轮次、报名截止、已审核、自审、名单锁定、重复确认和任务重试均不能绕过原服务规则。
- 恶意附件和提示注入不能提升权限；工具只提供最小字段，真实模型请求中不出现禁发字段。
- 页面上下文验收覆盖白名单外字段/图片/证件不外发、输入脱敏、客户端错误伪造、跨页迟到建议、草稿版本冲突及清空后迟到结果；可查看实际带入内容，不以用户“有权看原件”推定 AI 有权获取原件。
- 未登录直连、伪造 Origin/转发身份头、复制过期/已登出凭据均不能消耗模型额度；合法账号即使通过脚本调用，也受相同账号额度、并发、对象权限与工具限制。不得以“跨域请求被浏览器拦截”代替服务端验收。
