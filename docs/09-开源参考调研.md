## 3. 采用检查

1. 使用依赖或复制源码前，记录官方仓库、准确版本/commit、LICENSE/NOTICE 链接及拟使用方式。
2. 保留相应版权和 NOTICE；涉及 AGPL 或额外署名条款时，确认分发/网络服务义务与交付方式是否兼容，再决定使用。
3. “可学习概念”不等于“可直接复制实现”；任何许可证标签都不能替代对锁定版本条款的核对。

核验记录随实际依赖落地，不维护易过时的 star 排名或未经源码验证的能力断言。

## 4. 2026-11-18：响应式、交互组件与助手浮窗参考核验

本轮只研究官方站、官方文档及其源码，不安装依赖、不修改界面。正式技术栈仍为 Vue 3 + TypeScript + Element Plus，当前仅原生 JavaScript 静态原型。本节记录访问当日的公开资料，不代表已经选择依赖或锁定版本；采用前仍执行第 3 节的版本、LICENSE/NOTICE 与来源记录。

### 4.1 建议顺序与用途

1. **Element Plus 继续承担业务基础控件**：表单、筛选、表格、业务弹层和反馈遵循现有设计规范。
2. **Element-Plus-X 优先评估助手聊天内容**：气泡列表、推荐问题与输入器比装饰动效库更贴合对话场景；它是独立社区项目，不能当作 Element Plus 官方扩展。
3. **Inspira UI 优先用于 Vue 交互与视觉补充**：挑选网格、选中项过渡、点击反馈；逐个核对依赖和样式，不整套覆盖 Element Plus。
4. **Anime.js 作为按需动画候选**：现有静态原型与未来 Vue 都可使用；简单浮窗和消息过渡先用 CSS/Vue 内建过渡，需要受控时间线、拖动约束等再评估引入。
5. GSAP 适合更复杂的布局重排、时间线和拖动；21st.dev、React Bits、Aceternity UI、Originkit 主要提供跨框架交互参考；Uiverse 可挑选原生 HTML/CSS 微交互；Remotion 留给未来赛事宣传视频，不用于聊天浮窗。

以上是本项目适配顺序，不是库质量排名。响应式布局仍需按业务内容设计和验收；复制“支持移动端”的组件不会自动解决赛事卡片、筛选、表格及浮窗在窄屏的组合布局。

### 4.4 可落地的响应式与交互动效清单

| 场景 | 建议落地方式 | 验收重点 |
| --- | --- | --- |
| 门户赛事卡片 | 借鉴 Inspira Bento Grid 的分组层次，用项目自身 CSS 网格控制列数和卡片内容；真实标题、赛季、时间、状态与报名入口优先。 | 桌面到 375px 自然减列，长标题和英文不截断操作，无页面横向溢出。 |
| 搜索与状态筛选 | 保留 Element Plus/现有筛选入口，窄屏自动换行；借鉴 Morphing Tabs 的选中项移动反馈，结果数量及加载可见；需要结果重排动画时再评估 GSAP Flip。 | 动画不更改筛选语义、不丢失焦点和输入；筛选变化与结果更新对应，支持减少动效。 |
| 助手展开/收起 | 入口与非模态面板受控显示，使用 150–250ms 的透明度/短位移动画；需要多段协调时用 Anime.js Timeline。 | 展开不阻断业务点击，移动端保留两侧边距，不重建会话；尺寸继续遵循前端规范。 |
| 消息出现 | 借鉴 FadeContent/AnimatedContent 的进入节奏，以 Vue 过渡或局部 CSS 实现；BubbleList 管消息与滚动。 | 用户上翻阅读时不抢滚动；完整文本可读，流式内容不反复对整条消息播放进入动画。 |
| 按钮与加载反馈 | 借鉴 Ripple Button 的点击反馈及 Uiverse loader 的简单节奏，映射现有按钮和加载状态；发送、取消、错误重试有明确文字。 | 保留业务按钮语义与禁用/加载规则；无障碍名称明确，不让动画成为唯一状态说明。 |
| 拖动避让 | 若确有遮挡问题，评估 Anime.js Draggable 的 trigger/container 或 GSAP Draggable，拖动手柄与消息选择区域分开，限制在可视区域内。 | 拖动为可选增强；提供无需拖动的收起/复位方式，窗口缩小时重新约束；自动避让业务弹窗仍需项目设计，库不自动提供。 |

这些是建议方案，不表示已实现或已通过浏览器验收。装饰性粒子、全屏视差、持续光晕、重 3D/Shader 不进入后台高频任务区；赛事重点区确有用途时可另行评估。参考库不能替代焦点管理、响应式布局、减少动效、主题令牌及业务状态设计。
