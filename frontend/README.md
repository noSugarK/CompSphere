# compsphere-web

正式Vue 3 + TypeScript工程，复用Element Plus业务组件，使用Pinia、Vue Router、Axios、vue-i18n及Zod。锁定版本与可用命令见package.json/package-lock.json，接口见[开发契约](../docs/12-development-contract.md)。独立[静态演示](prototype/README.md)继续保留，不连接正式API，也不参与正式构建。

## 开发与检查

在仓库根目录执行：

```powershell
npm ci --prefix frontend
npm run api:generate --prefix frontend
npm run dev --prefix frontend -- --port 5174 --strictPort
```

后端先在127.0.0.1:8000运行，SITE_BASE_URL设置为实际前端origin（上例http://127.0.0.1:5174），开发服务将/api与/healthz代理至后端。使用后端显式创建的账号登录，无默认密码或前端假登录。生产由同源Nginx代理；开发服务只绑定本机。

```powershell
npm run lint --prefix frontend
npm run format:check --prefix frontend
npm run typecheck --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
```

api:generate从后端导出的docs/openapi.json生成src/api/generated.d.ts，不手工编辑；Zod运行时schema与生成类型交叉校验。HTTP响应以unknown进入结构校验，非法包裹/字段/枚举/ID/日期不会进入store。请求及AI提案也有独立严格schema；schema通过不代替服务端逐次授权。

## 当前实现

- 邮箱/证件登录、内存Access、Refresh Cookie/CSRF、单飞刷新、过期清理、账号切换旧请求隔离；无localStorage/sessionStorage token。
- 邮箱验证码注册与找回：严格校验6位ASCII验证码，保留前导零，注册后显式登录，重置不自动登录；202仅显示通用受理文案。发送成功按60秒契约冷却，真实429按有效Retry-After反馈；失败保留输入并定位字段，密码及验证码仅成功后清除。
- 中英及浅/深/system主题，门户赛事/详情、队伍概要、队伍提案/审核、赛季许可、报名草稿/提交/冻结/取消修改与单级审核页面，前端权限路由和按钮控制。
- Element Plus表单/表格/确认和状态反馈；加载/空/失败可重试，日期固定Asia/Shanghai；窄屏可操作，复杂批量仍以桌面为主。
- 消息中心参考静态演示的顶栏铃铛、日期分组和「查看」动作，读取真实报名进度，支持分页和标为已读。
- 赛事管理参考静态演示的目录和创建弹窗，展示权限内赛事；只有平台管理员可保存私有草稿。
- 平台赛季管理支持创建跨年草稿、激活、确认当前赛季切换，以及赛季名称/日期编辑与带二次确认的安全归档（归档仅对非当前 active 赛季展示，锁定与提示由服务端把关），普通门户仍只读展示当前赛季。
- 赛事目录可进入届次管理；有权管理员可选所属赛季并按北京时间录入报名与比赛时间，保存为私有草稿。目录行内提供赛事资料编辑（名称/简介/分类/级别，需 competition:update）、归档确认与平台专属的恢复（理由必填）；状态列同步展示已归档。
- 草稿届次可按稳定赛项类型编辑人数范围和教练要求；已发布届次的赛项只能启停。
- 届次配置的组别区支持学段、报名形式和年级条件；已发布组别只能启停，已有报名仍保留。
- 届次配置沿用静态原型的基本信息、报名规则、赛项与组别、发布检查四个分区。草稿可编辑名称、地点和报名/比赛时间，已发布基本信息与首期单级审核规则只读；各操作使用真实 API，不复用原型的模拟保存或两级审核选项。
- 开放组合区使用赛项 × 组别矩阵，区分未配置、启用和停用；草稿可覆盖北京时间的报名起止并配置参考名额。门户显示已启用组合的生效时间，进入新报名只能选择当前开放的组合。
- 报名按个人/团队选择流程加载服务端可选组合；团队先选队，再手动选择本场组别。修改既有报名不更换参赛方式或队伍，原组合仍显示以便核对。
- 审核页默认待审核，支持按届次、赛项、组别、单位、状态及报名编号/队号筛选；使用服务端授权范围和冻结组合，从详情返回保留筛选与页码。
- 报名详情按轮次分页显示冻结组合、可展开成员和审核时间线。审核确认标明报名编号和轮次；驳回、退回需要意见。
- 审核台桌面端可勾选本页待审核轮次，批量通过、退回或驳回。确认时列出编号和轮次，完成后报告成功/未处理数及逐条失败原因；手机保留单条审核。
- 奖项页（`/awards/:届次`）按「届次×赛项×组别」及通用档配置奖项、挑选已通过报名组名单并走提交/确认/驳回/解锁状态机；驳回与解锁意见必填并单次确认。名单公示设置三档可见性与字段白名单，公开页（`/editions/:届次/roster`）只渲染服务端交集字段，login 档未登录引导登录后回跳。
- 管理页提供发布清单和两级发布确认，不把草稿或非当前赛季届次展示到门户。
- 学生账户页（`/students`）供单位管理员按单位查看成员、代建无邮箱学生账户（幂等重试不再显示临时密码、一次性凭据弹窗）、核验重置密码，以及发起/提交/审核证件更正（末四位与依据版本可见，批准/退回/驳回理由必填）。禁用与管理角色分配仍仅平台。
- 管理工作台（`/console`）显示授权范围内的报名/通过/通过率/获奖计数及按赛项×组别分解，平台盘子仅 `stats:read_platform` 可见；操作记录页（`/audit-logs`）分页显示授权范围内事件，可按对象类型与日期过滤。
- 路由外AI悬浮入口仅显示未接入状态及最小页面标识，不调用模型、采集DOM/图片/附件或伪造业务成功。

本轮是核心链路，不代表完整首期已交付。组织入驻、赛事封面附件与主办/承办/协办单位配置、固定模板导入、材料安全上传、通用公告和自动备份等尚待后续实现；验证码及已启用的报名邮件实际送达取决于后端投递器及SMTP配置，HTTP成功不能证明邮件送达。获奖名单Excel导入、证书、复杂跨队特批和两级审核为后续范围。必交材料仍受后端校验，不能用当前无材料联调场次替代真实赛事验收。
